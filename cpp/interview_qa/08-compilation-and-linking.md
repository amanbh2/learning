# Interview Q&A: Compilation and Linking Process

*(Companion to [Note 08](../08-compilation-and-linking-process.md))*

**Q: Can we write C++ code to do something without including ANY header file?**
**A:** Yes, absolutely! Header files are not the C++ language itself; they just contain declarations for libraries. All core language features (variables, loops, `if`/`else`, classes, math, pointers, and memory allocation) are built directly into the compiler. You can write a fully functional program that calculates complex logic and returns an exit code to the OS without a single `#include`. You only need headers when you want to interact with the OS (like `std::cout` to print to the screen) or use pre-written library code (like `std::vector`).

**Q: Do file extensions like `.cpp` or `.h` actually mean anything to the C++ compiler?**
**A:** No. File extensions in C++ are purely conventional for human readability and to help build tools (like Make or CMake) recognize file types. To the compiler, they are just plain text files. The preprocessor literally copies and pastes the contents of a `#include` regardless of whether the file ends in `.h`, `.hpp`, or `.mango`. You can even compile a file with no extension by explicitly telling the compiler it contains C++ code (e.g., `g++ -x c++ my_file`).

**Q: Where does a C or C++ program start executing, and are there rules on what that file must be named?**
**A:** Execution strictly begins at a function named `main()`. This is a hard rule enforced by the Linker. However, there are **no rules** regarding what the file containing `main()` is named. While it is conventionally named `main.cpp` for human readability, it could be named `start.cpp` or `logic.cpp`. As long as the Linker finds `int main()` inside one of the compiled object files, the program will run. Furthermore, the C/C++ language standards impose zero limitations on filenames—any limitations come strictly from your OS (e.g., illegal characters in Windows) or your build system.

**Q: Can you define `main()` as `void main()`? What happens if you forget to return an integer in `int main()`?**
**A:** According to the C++ language standard, `main()` **must** return an `int`. Writing `void main()` is strictly illegal, although some very old non-compliant compilers used to allow it. The OS explicitly expects an integer exit code to determine if the program crashed. 
Interestingly, if you define `int main()` but forget to write a `return` statement at the bottom, the compiler will implicitly insert `return 0;` for you. This is a unique exception in C++; if you forget a return statement in *any other* function returning an `int`, it results in Undefined Behavior.

**Q: In boolean logic, `0` is false (failure). Why does returning `0` from `main()` mean "success"?**
**A:** OS exit codes operate on a different philosophy: **There is only one way to succeed, but hundreds of ways to fail.** By reserving `0` for "Success" (no errors), the Operating System leaves all positive integers (1-255) available to communicate *specific* error codes. If `1` meant success, the OS would only have `0` to represent a failure. Because of this design, returning `1` might mean "File not found", while returning `139` means a "Segmentation Fault".

**Q: Why is it difficult to use GDB to debug a core dump generated by a Release build (`-O3`)?**
**A:** In a Release build, the compiler applies heavy optimizations (like `-O3`). It will unroll loops, inline functions, and completely erase variables that it deems mathematically redundant. Because the resulting machine code looks nothing like the original C++ source code, stepping through it in GDB is nearly impossible. Additionally, Release builds usually strip out debug symbols (`-g`), meaning GDB only sees raw memory addresses instead of human-readable line numbers and variable names.

**Q: Why do professional C++ codebases enforce the `-Werror` (or `/WX`) compiler flag?**
**A:** By default, C++ compilers are very permissive and will compile code that contains obvious logic flaws (like using uninitialized variables) while only emitting a "Warning". The `-Werror` flag tells the compiler to treat all warnings as fatal errors, instantly halting compilation. This forces developers to write perfectly clean, explicit code and prevents dangerous bugs from sneaking into production binaries.
